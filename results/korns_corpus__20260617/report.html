CuSR corpus: Korns inner-constant (frequency-class) trees on the A100 pipeline

2026-06-17

问题 / Question. 把内部常数(藏在 cos/sin 频率里、线性拟合解不出、CO 才有用)的题接进 A100 采集流水线,跑出一份真实 GP 语料,作为后续端到端 CO 实验的‘CO 该发光’主战场。Wire inner-constant targets (constants buried in cos/sin frequencies — unfittable by linear scaling, where CO is decisive) into the A100 harvest pipeline and produce a real GP corpus, as the 'CO should shine' battlefield for the planned end-to-end CO experiment.

实验设置 / Setup. 在 sr_problems.py + dump_evogp.py 的共享题库加 korns/11、korns/12(逐字一致,过 AST parity 测试),GP 算子集沿用 {+,-,*,/,sin,cos,tan}(korns/11 的 x^3 仅生成 y,GP 用 x*x*x 近似),用现有 harvest.py 在 GPU 1-5 并行采集。kernel 画像:FD 与 AD 在 cap64/无噪/seed0 上跑。Added korns/11 & korns/12 to the shared problem library in sr_problems.py + dump_evogp.py (byte-identical, AST parity test passes); GP funcset unchanged {+,-,*,/,sin,cos,tan} (korns/11's x^3 only generates y, GP approximates via x*x*x); harvested with the existing harvest.py on GPUs 1-5. Kernel profile: FD and AD on cap64/noiseless/seed0.

发现 / Findings

【内部常数工况·建成】两道频率类 Korns 题语料已采成:真实常数藏在 cos/sin 内部(korns/11 内部常数 1 个=频率 7.23;korns/12 内部常数 2 个=频率 9.8 与 1.3),线性最小二乘无法拟合 → CO 在此才有决定性作用。对照 17 题 Feynman+Nguyen 语料内部常数≈0。[inner-const regime · built] Corpus harvested for the two frequency-class Korns targets: true constants sit INSIDE cos/sin (korns/11 has 1 inner const = freq 7.23; korns/12 has 2 = freqs 9.8 & 1.3) — linear least-squares cannot fit them, so CO is decisive here. Contrast the 17-problem Feynman+Nguyen corpus (inner consts ≈ 0).
证据 / evidence: 24 cell / 216 快照 / 864,000 棵树,0 丢弃、0 K-over。矩阵:2 题 × 噪声{0,1%} × cap{32,64} × seed{0,1,2} × gen{0,1,2,4,8,16,32,64,100},pop=4000,N=1000。24 cells / 216 snapshots / 864,000 trees, 0 dropped / 0 K-over. Matrix: 2 problems × noise{0,1%} × cap{32,64} × seed{0,1,2} × gen{0..100}, pop=4000, N=1000.
【负载差异=膨胀时机,非终点】两题晚期都膨胀到相近的高 K(cap64 gen100:korns/11 K=12.7、korns/12 K=12.3),差别在膨胀的早晚:korns/11(立方+高频,目标近乎不可解)很早就膨胀(gen16 已 K=14.0),korns/12(两个中等频率)中期仍稀疏(gen16 K=1.9)、到晚期才膨胀。=> 干净的低 K 工作点在 korns/12 的早/中代。[workload difference = bloat TIMING, not endpoint] Both bloat to a similar high K by late gen (cap64 gen100: korns/11 K=12.7, korns/12 K=12.3); the difference is WHEN: korns/11 (cube+high-freq, near-unsolvable) bloats early (K=14.0 already at gen16), while korns/12 (two moderate freqs) stays sparse through mid-gen (K=1.9 at gen16) and only bloats late. => the clean low-K operating point is korns/12 at early/mid gen.
证据 / evidence:
【kernel 正常运行;秩亏随膨胀走,非内部常数本身】FD 与 AD 在两题上均无崩溃、有限返回。Cholesky 失败率随 bloat 走:早/中代低(korns/11 gen4 13%、korns/12 gen16 25%),晚代两题都塌成秩亏(gen100 cap64 korns/11 83%、korns/12 94%)——与 Feynman 语料同一个‘膨胀→秩亏’机制。=> 干净的 CO 工作区是早/中代。[kernel runs fine; rank-deficiency tracks bloat, not inner-consts per se] FD and AD both run crash-free with finite returns on both. Cholesky-fail tracks bloat: low at early/mid gen (korns/11 gen4 13%, korns/12 gen16 25%), and both collapse to rank-deficient at late gen (gen100 cap64 korns/11 83%, korns/12 94%) — the SAME 'bloat→rank-deficiency' mechanism as the Feynman corpus. => the clean CO operating regime is early/mid gen.
证据 / evidence: kernel 状态(converged/fail)是工况描述符,非质量判定——见 caveats(operon_baseline 已证status==0 不等于真改进)。FD 收敛率(按状态)略高于 AD,但这不是质量结论。kernel status (converged/fail) is a workload descriptor, NOT a quality verdict — see caveats (operon_baseline showed status==0 ≠ genuine improvement). FD's status-converged rate is marginally higher than AD's, but that is not a quality conclusion.

注意事项 / Caveats

  • kernel 的 converged/fail 是工况描述符,不是质量判定:operon_baseline 已证 status==0 ≠ 真改进。质量需用中立 fp64 评分,留到端到端实验。kernel converged/fail is a workload descriptor, not a quality verdict: operon_baseline showed status==0 ≠ genuine improvement. Quality needs neutral fp64 scoring — deferred to the end-to-end experiment.
  • korns/11 的立方+高频目标在 [-5,5] 上是公认的‘已知天花板’,即便 CO 完美也基本不可解;它在这里是高 K + 秩亏压力工况,不是干净的‘CO 展示’题。korns/12 才是主展示题。korns/11's cube+high-freq target on [-5,5] is a known ceiling — near-unsolvable even with perfect CO; here it serves as a high-K + rank-deficiency stress workload, not a clean 'CO demo'. korns/12 is the demo target.
  • 这是语料(真实树)+ 工况画像,不是端到端实验:它不衡量‘CO 是否提升公式恢复’,只提供后续实验的输入。This is a corpus (real trees) + workload characterization, NOT the end-to-end experiment: it does not measure 'does CO improve formula recovery', it only supplies the input for that experiment.
  • GP 算子集无 POW;korns/11 的 x^3 由乘法近似(同 Nguyen log/sqrt 题的处理),是 y 生成器而非 GP 约束。GP funcset has no POW; korns/11's x^3 is approximated by multiplication (same as the Nguyen log/sqrt entries) — a y-generator, not a GP constraint.
