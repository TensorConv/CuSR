## 二、核心算法的实验结果（论文的主角，我负责）

- [ ] **4. 跑性能剖析——但别拿经典 roofline 当主角。** 实测我们这 kernel 只用到算力峰值和带宽峰值的 **<1%（两条都不到 1%）**，所以经典 FLOP-roofline 只会画出"远在两条线下方的一个点"，根本说不清瓶颈在哪。**主诊断换成 ncu 的 Speed-of-Light + warp-stall 原因分解**（看时间耗在哪：超越函数挤 SFU、栈机的依赖链、分支发散）。**要 roofline 形状的图，就用 instruction roofline**（按"指令"算、不按 FLOP 算，专给我们这种"发射受限"的 kernel）。经典 FLOP-roofline 只留一句反证——"不是带宽/算力 bound"，正好堵住"那你为什么不做显存布局优化"。
- [ ] **5. 规模扫描（锁频干净版）。** 三个求导方法（有限差分/前向/反向）扫 M×N×树种、跨 3 seed 取中位、每点过双精度质量门——论文最主要那张性能表/图。**收窄：Operon 免跑**（e6 已有 162 条、CPU 跑的、跟锁频/反向求导无关，复用 + 离线配对做同条件对比，另跑几个哨兵确认没漂）。等机器空、锁全 8 卡跑。详见 `tasks/05`（含 codex 复查后的修正）。
- [ ] **6. 反向 vs 前向。** 速度从第 5 条扫描取个切片就有；质量等价已做（`analyze_ad_vs_fd_ranking`：排序等价、AD≈FD）。基本不用额外烧卡。
